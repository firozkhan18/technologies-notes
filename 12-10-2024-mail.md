A thread is the smallest unit of processing that can be scheduled by the operating system. In Java, a thread is an instance of the `Thread` class or implements the `Runnable` interface.

#### Creating Threads:
You can create threads in Java in two main ways:

1. **By Extending the Thread Class**:
   ```java
   class MyThread extends Thread {
       @Override
       public void run() {
           System.out.println("Thread running: " + Thread.currentThread().getName());
       }
   }

   public class ThreadExample {
       public static void main(String[] args) {
           MyThread thread = new MyThread();
           thread.start(); // Start the thread
       }
   }
   ```

2. **By Implementing the Runnable Interface**:
   ```java
   class MyRunnable implements Runnable {
       @Override
       public void run() {
           System.out.println("Runnable running: " + Thread.currentThread().getName());
       }
   }

   public class RunnableExample {
       public static void main(String[] args) {
           Thread thread = new Thread(new MyRunnable());
           thread.start(); // Start the thread
       }
   }
   ```
   
### 1. **What is Multithreading?**
   - **Definition**: Multithreading is the ability to execute multiple threads concurrently within a single process. It helps to make the application more efficient and responsive by performing multiple operations simultaneously.
   - **Advantages**:
     - Lightweight threads that share the same address space.
     - Efficient memory and resource usage.
     - Faster execution as threads run independently.

### 2. **What is a Thread?**
   - A **thread** is a lightweight process that has its own execution path. It is a part of a process and runs concurrently with other threads within the same process. Threads share the process's resources but operate independently.

### 3. **Difference Between Process and Thread**:
   - **Process**: A process has its own memory and resources.
   - **Thread**: A thread is part of a process and shares the process's memory but executes independently.

### 4. **Inter-thread Communication**:
   - Inter-thread communication allows threads to communicate with each other using `wait()`, `notify()`, and `notifyAll()` methods.
   - These methods help synchronize access to shared resources and avoid deadlock.

### 5. **Thread States**:
   - **New**: A thread is created but not yet started.
   - **Runnable**: Thread is ready and waiting for CPU allocation.
   - **Running**: The thread is executing.
   - **Blocked/Waiting**: The thread is waiting for a resource or condition.
   - **Terminated**: The thread has finished execution.

### 6. **Wait vs. Sleep**:
   - **`wait()`**: Used for inter-thread communication and must be called from a synchronized block. It pauses the thread until it is notified.
   - **`sleep()`**: Pauses the thread for a specified time but doesn't release the lock on the object.

### 7. **`join()` Method**:
   - **`join()`** allows one thread to wait for the completion of another thread before it continues execution.

### 8. **Daemon Threads**:
   - Daemon threads run in the background and are terminated by the JVM once the main (user) threads finish. They provide support services for user threads.
   - **Methods**: `setDaemon(true)` and `isDaemon()`.

### 9. **Thread Synchronization**:
   - **Synchronized methods**: Locks the entire method for thread-safe operations.
   - **Synchronized blocks**: Locks only the critical section, providing better performance.

### 10. **BlockingQueue**:
   - **BlockingQueue** is a thread-safe queue used in producer-consumer scenarios. It blocks a thread if the queue is empty or full until conditions change.
   - **Example**: Producer thread inserts elements, while the consumer thread takes them.

### 11. **Deadlock**:
   - A **deadlock** occurs when two or more threads are blocked forever, each waiting for the other to release resources. Deadlock can be prevented by avoiding nested locks and ensuring threads acquire resources in a fixed order.

### 12. **CyclicBarrier vs. CountDownLatch**:
   - **CyclicBarrier**: Used to synchronize a group of threads at a common barrier point.
   - **CountDownLatch**: Used to block a thread until a set of threads have completed their execution.

### 13. **Thread Priority**:
   - Threads in Java have priorities that the JVM scheduler can use to determine the order of execution. The priority range is from `Thread.MIN_PRIORITY (1)` to `Thread.MAX_PRIORITY (10)`.

### 14. **ThreadLocal**:
   - `ThreadLocal` provides thread-local variables, where each thread has its own independent copy. It is useful in avoiding synchronization problems.

### 15. **Semaphore**:
   - A **semaphore** controls access to shared resources by multiple threads. It uses counters to limit the number of threads that can access the resource simultaneously.

### 16. **Busy Spinning**:
   - **Busy spinning** (or busy-waiting) happens when a thread repeatedly checks for a condition in a loop without releasing CPU resources, which can lead to inefficient resource use.

### 17. **Context Switching**:
   - **Context switching** refers to saving and restoring the state of a thread or process so that it can be resumed later, enabling multitasking.

### 18. **Thread Starvation**:
   - **Thread starvation** occurs when a thread cannot gain regular access to resources because other threads with higher priority consume all the CPU time.

### 19. **Thread Scheduling**:
   - **Preemptive scheduling**: A thread with higher priority can preempt the CPU from a lower priority thread.
   - **Time-slicing**: Each thread gets a fixed time slice to execute, after which the CPU is given to another thread.

### 20. **`finalize()` Method**:
   - **`finalize()`** is a method used to perform cleanup operations on unmanaged resources just before garbage collection.

### 21. **`notify()` vs. `notifyAll()`**:
   - **`notify()`** wakes up a single thread that is waiting on the object.
   - **`notifyAll()`** wakes up all threads that are waiting on the object.

### 22. **Thread Group**:
   - **ThreadGroup** is used to manage multiple threads, though it is generally discouraged due to its limited functionality and poor support for advanced thread management.

### 23. **Synchronized Method vs. Synchronized Block**:
   - **Synchronized method** locks the entire method for thread-safe execution.
   - **Synchronized block** locks only the critical section, improving performance by not locking the entire method.

### 24. **What is the `run()` Method?**
   - The **`run()`** method defines the code that will be executed by the thread. If not overridden, the `Thread` class's `run()` method executes nothing.

### 25. **Why Not to Call `run()` Directly?**
   - Calling `run()` directly will not start a new thread. Instead, it will execute on the current thread. To start a new thread, use `start()` method.

### Concurrent HashMap

A **ConcurrentHashMap** is a thread-safe variant of `HashMap` designed for concurrent use. It allows multiple threads to read and write simultaneously without locking the entire map, improving performance and scalability.

#### Example of ConcurrentHashMap

```java
import java.util.concurrent.ConcurrentHashMap;

public class ConcurrentHashMapExample {
    public static void main(String[] args) {
        ConcurrentHashMap<String, Integer> map = new ConcurrentHashMap<>();

        // Populate the map
        map.put("One", 1);
        map.put("Two", 2);
        map.put("Three", 3);

        // Accessing the map concurrently
        Runnable task = () -> {
            String threadName = Thread.currentThread().getName();
            for (String key : map.keySet()) {
                System.out.println(threadName + " read: " + key + " = " + map.get(key));
            }
        };

        Thread t1 = new Thread(task);
        Thread t2 = new Thread(task);
        
        t1.start();
        t2.start();
    }
}
```
### Executor Framework

The **Executor framework** in Java provides a high-level API for managing and controlling threads. It decouples task submission from the details of how each task will be run, allowing better resource management and flexibility.

The Executor Framework in Java provides a higher-level replacement for managing threads directly. It simplifies thread management and allows for more scalable and maintainable code.

#### Key Components

1. **Executor Interface**: The simplest interface to provide a way to execute a runnable task.

2. **ExecutorService**: An interface that provides methods for managing and controlling the execution of tasks. Extends `Executor` and provides methods to manage the lifecycle of the executor (like shutdown).

3. **ScheduledExecutorService**: Extends `ExecutorService` to schedule commands to run after a given delay or periodically.

4. **ThreadPoolExecutor**: A versatile implementation of `ExecutorService` that allows managing a pool of threads.

#### Example of Executor Framework

```java
import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;

public class ExecutorFrameworkExample {
    public static void main(String[] args) {
        // Create a thread pool with 3 threads
        ExecutorService executorService = Executors.newFixedThreadPool(3);

        Runnable task = () -> {
            String threadName = Thread.currentThread().getName();
            System.out.println("Task executed by: " + threadName);
        };

        // Submit tasks to the executor
        for (int i = 0; i < 5; i++) {
            executorService.submit(task);
        }

        // Shutdown the executor
        executorService.shutdown();
    }
}
```
#### Example 2:

### 2. **Concurrency Classes & Interfaces**

#### **Executor Framework (java.util.concurrent)**:
The **Executor Framework** provides a higher-level replacement for managing and controlling thread execution. This framework abstracts the thread management complexities and provides classes and interfaces that help with task execution and management.

- **Executor Interface**:
  - The **Executor** interface is the core of the Executor framework. It provides a simple interface to execute tasks asynchronously.
  - **Method**: 
    - `void execute(Runnable command)`: Executes the given task (Runnable) asynchronously.

- **ExecutorService Interface**:
  - A more advanced interface that extends **Executor** and adds features like shutting down the executor and submitting tasks that return results.
  - **Methods**:
    - `void submit(Callable<T> task)`: Submits a task for execution and returns a `Future`.
    - `void shutdown()`: Initiates an orderly shutdown of the executor service.
    - `List<Runnable> shutdownNow()`: Attempts to stop all actively executing tasks and halts the processing of waiting tasks.
  
- **ScheduledExecutorService Interface**:
  - Extends **ExecutorService** and provides methods for scheduling tasks at fixed-rate intervals or with fixed-delay.
  - **Methods**:
    - `ScheduledFuture<?> schedule(Runnable command, long delay, TimeUnit unit)`: Schedules a task with a fixed delay.

#### **Executor Implementations**:
- **ThreadPoolExecutor**:
  - A powerful implementation of **ExecutorService**, which allows you to manage a pool of worker threads.
  - **Constructor Parameters**: Core pool size, maximum pool size, keep-alive time, and blocking queue.
  - **Methods**: 
    - `int getActiveCount()`: Returns the number of threads actively executing tasks.
    - `int getCorePoolSize()`: Returns the core pool size.
  
- **ScheduledThreadPoolExecutor**:

  - Represents the result of an asynchronous computation.
  - **Methods**:

- **Callable Interface**:
  - Similar to **Runnable**, but it can return a result and can throw an exception.
  - **Method**:
    - `V call() throws Exception`: Executes the task and returns a result.

    - `void put(E e) throws InterruptedException`: Inserts the element, blocking if necessary.

Provides a more flexible alternative to **synchronized** blocks/methods for managing concurrency.

- **Methods**:
  - `void lock()`: Acquires the lock.

  - `void unlock()`: Releases the lock.
  - `Condition newCondition()`: Returns a new **Condition** instance associated with the lock.

#### **ReentrantLock**:

  - `boolean tryLock(long time, TimeUnit unit)`: Attempts to acquire the lock within a specified time limit.

#### **Condition Interface**:
Allows threads to coordinate their execution by signaling each other.
- **Methods**:
  - `void await() throws InterruptedException`: Causes the current thread to wait until it is signaled.
  - `void signal()`: Wakes up one waiting thread.
  - `void signalAll()`: Wakes up all waiting threads.

#### **ReadWriteLock Interface**:
A **Lock** implementation that allows multiple threads to read the resource simultaneously, but only one thread to write to the resource.
- **Methods**:
  - `Lock readLock()`: Returns a lock for read access.
  - `Lock writeLock()`: Returns a lock for write access.

#### **ReentrantReadWriteLock**:
- A **ReadWriteLock** implementation that allows threads to hold a read lock or a write lock, but only one thread can hold the write lock at a time.
- **Methods**:
  - `boolean tryWriteLock(long time, TimeUnit unit)`: Tries to acquire the write lock within a given time.

Concurrency issues arise in multi-threaded programming due to the complexities of sharing resources and coordinating threads. These issues can lead to errors such as deadlocks, race conditions, thread contention, and others. Below, I'll outline common concurrency problems along with their prevention techniques.

---

### 1. **Common Concurrency Issues**

#### **1.1 Race Condition**
- **Definition**: A race condition occurs when two or more threads access shared data simultaneously, and the final outcome depends on the non-deterministic order in which the threads execute.
- **Example**: A bank account with two threads trying to deposit money at the same time.
  - Without synchronization, both threads could read the same balance, modify it, and write it back, causing the final balance to be incorrect.

- **Prevention**:
  - Use **synchronized blocks/methods** to ensure mutual exclusion.
  - Use **locks** (like **ReentrantLock**) to lock access to critical sections.
  - **Atomic variables** (e.g., **AtomicInteger**, **AtomicLong**) for thread-safe operations without needing explicit synchronization.
  
  ```java
  synchronized (account) {
      account.deposit(amount);
  }
  ```

#### **1.2 Deadlock**
- **Definition**: A deadlock occurs when two or more threads are blocked indefinitely, waiting for each other to release resources. This leads to a situation where none of the threads can proceed.
- **Example**: Thread A locks resource 1 and waits for resource 2, while thread B locks resource 2 and waits for resource 1.
  
- **Prevention**:
  - **Lock ordering**: Always acquire locks in a consistent order to avoid circular dependencies.
  - **TryLock**: Use `tryLock()` with a timeout to avoid waiting indefinitely.
  - **Timeout-based mechanisms**: Set a timeout for lock acquisition and back off if the lock is not acquired within the timeout period.

  ```java
  if (lockA.tryLock() && lockB.tryLock()) {
      try {
          // Critical section
      } finally {
          lockA.unlock();
          lockB.unlock();
      }
  }
  ```

#### **1.3 Thread Starvation**
- **Definition**: Thread starvation happens when a thread is perpetually denied access to resources, usually because higher-priority threads are always executing.
- **Example**: In a system with high-priority threads, lower-priority threads may never get CPU time to run.
  
- **Prevention**:
  - Use **fair locks** or **fair executors** to ensure that threads are executed in the order they request access to the resource.
  - **Adjust thread priorities** appropriately.
  - Use **`ReentrantLock` with fairness set to true** to ensure a fair distribution of lock acquisition.

#### **1.4 Thread Interference**
- **Definition**: Thread interference happens when multiple threads try to update shared data at the same time in a way that causes inconsistency or corruption of the shared data.
- **Example**: Two threads modifying a shared variable without synchronization can lead to an inconsistent or incorrect value.

- **Prevention**:
  - **Synchronized blocks/methods**: Ensure that shared resources are accessed in a mutually exclusive manner.
  - **Atomic classes** (e.g., **AtomicInteger**) to prevent interference on simple operations like incrementing or updating.
  
  ```java
  synchronized (sharedResource) {
      // Modify shared resource
  }
  ```

#### **1.5 Priority Inversion**
- **Definition**: Priority inversion occurs when a low-priority thread holds a resource needed by a high-priority thread, causing the high-priority thread to be delayed.
- **Example**: A high-priority thread is waiting for a lock that is held by a low-priority thread, which in turn is preempted by an intermediate-priority thread.

- **Prevention**:
  - **Priority inheritance**: Some systems provide mechanisms for the low-priority thread to temporarily inherit the priority of the high-priority thread while holding the resource.
  - **Avoid using priority for synchronization**: Where possible, avoid relying on thread priorities for critical resources.

---

### 2. **Concurrency Deadlock and Starvation Prevention Techniques**

#### **2.1 Using `Lock` and `Condition`**
   - **`ReentrantLock`** allows the use of **Condition variables** to manage threads waiting for certain conditions to occur (like resources becoming available). This provides more flexibility than the basic `synchronized` block.

   - **Prevention**:
     - Use `tryLock()` or `lockInterruptibly()` methods to avoid indefinite waiting and reduce the chance of deadlock.
     - Use timeouts (`tryLock(long timeout, TimeUnit unit)`) to limit waiting for locks.
  
#### **2.2 Use of `ThreadPoolExecutor` with Fairness**
   - **Fairness**: The **ThreadPoolExecutor** constructor provides an option to use a fair scheduling policy. When fair is set to true, the executor ensures that threads are executed in the order they are submitted.

   - **Prevention of starvation**:
     - Set fairness to true while creating the executor:
       ```java
       ExecutorService executor = new ThreadPoolExecutor(1, 1, 0L, TimeUnit.MILLISECONDS,
                                                      new LinkedBlockingQueue<Runnable>(), 
                                                      new ThreadPoolExecutor.DiscardPolicy());
       ```

#### **2.3 Deadlock Detection**
   - In systems that are highly concurrent, it is useful to periodically check for possible deadlocks.
   - **JVM-based tools**: Tools like **jconsole** or **VisualVM** can help detect and monitor deadlocks in live applications.
   - **Deadlock detection algorithms**: Implement custom monitoring to periodically check for cyclic dependencies between threads and resources.

#### **2.4 Timeout-based Locks**
   - When acquiring locks, **timeouts** can be used to avoid waiting forever, thus preventing thread starvation.
   - Use **`ReentrantLock.tryLock(long timeout, TimeUnit unit)`** to avoid blocking indefinitely.

#### **2.5 Use of `CyclicBarrier` or `CountDownLatch`**
   - Use **CountDownLatch** or **CyclicBarrier** to manage thread synchronization in scenarios where threads need to coordinate with each other (e.g., waiting for all threads to finish a certain task before proceeding).

---

### 3. **General Guidelines to Prevent Thread and Concurrency Issues**

#### **3.1 Minimize Shared Resources**
- **Immutable Objects**: Use immutable objects where possible to reduce synchronization requirements. Immutable objects can be safely shared among threads.
  
#### **3.2 Minimize Lock Contention**
- **Lock granularity**: Minimize the amount of code that is protected by locks. Hold locks for the shortest time necessary to perform the required actions.
- **Avoid nested locks**: Avoid acquiring multiple locks simultaneously whenever possible. This reduces the chances of deadlock.

#### **3.3 Fine-Grained Synchronization**
- Instead of locking large sections of code, break down the critical sections into smaller parts and synchronize only the smallest possible block of code necessary for thread safety.

#### **3.4 Use Concurrent Data Structures**
- Java’s **`java.util.concurrent`** package provides thread-safe data structures like **`ConcurrentHashMap`**, **`CopyOnWriteArrayList`**, and **`BlockingQueue`**, which help avoid synchronization issues when accessing shared data.

#### **3.5 Minimize the Use of `Thread.sleep()`**
- **Thread.sleep()** introduces artificial delays that might cause other threads to be blocked unnecessarily.
- Prefer using **`wait()`, `notify()`, or `Condition`** for thread coordination, as these methods are designed for efficient thread interaction.

---

### Conclusion: Best Practices for Preventing Concurrency Issues

- **Minimize Shared State**: Design systems to avoid shared resources where possible. If shared state is necessary, ensure proper synchronization.
- **Use Concurrency Utilities**: Leverage utilities provided by `java.util.concurrent` like `ExecutorService`, `Locks`, `Atomic Variables`, `Concurrent Collections`, etc.
- **Understand Thread Lifecycle**: Know when threads are executing, waiting, or blocked to avoid unnecessary blocking.
- **Test and Monitor**: Continuously test your code under different concurrency loads and monitor runtime behavior with tools like **VisualVM** or **JConsole**.
- **Follow Patterns**: Use established design patterns like **Producer-Consumer**, **Read-Write Lock**, and **Fork/Join** to manage concurrency effectively.

By following these guidelines and being aware of the potential issues, you can write safer, more efficient concurrent applications.

### 1. Synchronous Execution

**Synchronous execution** means that the caller waits for the task to complete before proceeding. You can achieve this with the basic thread model or using the Executor framework.

#### Example Using Threads

```java
class SynchronousTask extends Thread {
    @Override
    public void run() {
        try {
            Thread.sleep(1000); // Simulating a long-running task
            System.out.println("Task completed: " + Thread.currentThread().getName());
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        }
    }
}

public class SynchronousExecutionExample {
    public static void main(String[] args) {
        SynchronousTask task = new SynchronousTask();
        task.start(); // Start the thread
        try {
            task.join(); // Wait for the task to complete
        } catch (InterruptedException e) {
            e.printStackTrace();
        }
        System.out.println("Main thread proceeding after task completion.");
    }
}
```

#### Example Using Executor Framework

```java
import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;
import java.util.concurrent.Future;

public class SynchronousExecutorExample {
    public static void main(String[] args) {
        ExecutorService executorService = Executors.newSingleThreadExecutor();

        Future<String> future = executorService.submit(() -> {
            Thread.sleep(1000); // Simulating a long-running task
            return "Task completed";
        });

        try {
            String result = future.get(); // Blocks until the task completes
            System.out.println(result);
        } catch (Exception e) {
            e.printStackTrace();
        } finally {
            executorService.shutdown();
        }

        System.out.println("Main thread proceeding after task completion.");
    }
}
```

### 2. Asynchronous Execution

**Asynchronous execution** allows the caller to continue processing without waiting for the task to complete. This can be achieved using threads or the Executor framework.

#### Example Using Threads

```java

    @Override
    public void run() {
        try {
            Thread.sleep(1000); // Simulating a long-running task
            System.out.println("Asynchronous task completed: " + Thread.currentThread().getName());
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        }
    }
}

public class AsynchronousExecutionExample {
```

### Executor framework and concurrency concepts in depth.

### 1. Understanding Concurrency

**Concurrency** refers to the ability of a program to execute multiple tasks simultaneously. In Java, concurrency is achieved through threads, which are lightweight processes. The Java platform provides built-in support for multithreaded programming, enabling developers to create highly responsive applications.

#### Key Concepts in Concurrency

- **Thread**: The smallest unit of processing that can be scheduled by the operating system. In Java, you can create a thread by implementing the `Runnable` interface or extending the `Thread` class.

- **Synchronization**: This is a mechanism that ensures that only one thread can access a resource at a time. Java provides various synchronization constructs like `synchronized` blocks and methods, locks, and concurrent collections to manage access to shared resources.

- **Deadlock**: A situation where two or more threads are blocked forever, each waiting for the other to release a resource. Avoiding deadlocks involves careful design, such as acquiring locks in a consistent order.

- **Race Condition**: This occurs when two or more threads access shared data and try to change it at the same time. Proper synchronization can help prevent race conditions.

### 2. The Executor Framework

The **Executor framework** in Java provides a higher-level replacement for managing threads. It simplifies the process of handling thread creation, execution, and management.

#### Key Interfaces and Classes

- **Executor**: This is a simple interface that represents an object that executes submitted `Runnable` tasks. It has a single method: `void execute(Runnable command)`.

- **ExecutorService**: This interface extends `Executor` and provides methods for managing and controlling the execution of tasks. It allows you to submit tasks and track their progress and results.

- **ScheduledExecutorService**: This is a sub-interface of `ExecutorService` that supports scheduling tasks to run after a delay or periodically.

- **ThreadPoolExecutor**: A concrete implementation of `ExecutorService` that provides a pool of threads to execute tasks. It manages a pool of worker threads and can dynamically adjust the number of threads based on the workload.

- **Future**: This interface represents the result of an asynchronous computation. You can use it to retrieve the result of a task after it has completed.

#### Basic Example

Here’s a simple example of using the Executor framework to run tasks:

```java
import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;

public class ExecutorExample {
    public static void main(String[] args) {
        ExecutorService executorService = Executors.newFixedThreadPool(3); // Create a thread pool with 3 threads

        for (int i = 0; i < 10; i++) {
            int taskId = i;
            executorService.submit(() -> {
                System.out.println("Task " + taskId + " is running in " + Thread.currentThread().getName());
                try {
                    Thread.sleep(1000); // Simulate work
                } catch (InterruptedException e) {
                    Thread.currentThread().interrupt();
                }
                System.out.println("Task " + taskId + " completed in " + Thread.currentThread().getName());
            });
        }

        executorService.shutdown(); // Initiates an orderly shutdown
    }
}
```

Circular dependency occurs when two or more beans in a Spring application depend on each other, either directly or indirectly. This can lead to issues such as `BeanCurrentlyInCreationException`. Here are several strategies to avoid or resolve circular dependencies in a Spring Boot application:

### 1. **Constructor Injection vs. Setter Injection**

Constructor injection creates a new instance of a bean and requires all dependencies to be provided at creation time. If two beans are dependent on each other, this can lead to a circular dependency.

#### Example of Circular Dependency

```java

    private final ServiceB serviceB;

    public ServiceA(ServiceB serviceB) {
        this.serviceB = serviceB;
    }
}

@Service

    private final ServiceA serviceA;

    @Autowired
    public ServiceB(ServiceA serviceA) {

    }
```

#### Using Setter Injection

### 3. **Using `@Lazy` Annotation**

The `@Lazy` annotation allows Spring to create a proxy for the bean, which can help resolve circular dependencies. This way, the actual bean is not instantiated until it is needed.

#### Example Using `@Lazy`

```java
@Service
public class ServiceA {
    private final ServiceB serviceB;

    @Autowired
    public ServiceA(@Lazy ServiceB serviceB) {
        this.serviceB = serviceB;
    }
}

@Service
public class ServiceB {
    private final ServiceA serviceA;

    @Autowired
    public ServiceB(@Lazy ServiceA serviceA) {
        this.serviceA = serviceA;
    }
}
```

### 4. **Event Listeners**

If the dependencies are more about event-driven behavior, consider using Spring’s event mechanism. This allows you to decouple components that need to communicate.

#### Example Using Event Listeners

```java
@Service
public class ServiceA {
    @Autowired
    private ApplicationEventPublisher publisher;

    public void doSomething() {
        // Some logic
        publisher.publishEvent(new MyCustomEvent(this));
    }
}

@Service
public class ServiceB {
    @EventListener
    public void handleCustomEvent(MyCustomEvent event) {
        // Handle the event
    }
}
```

### 5. **Application Context Aware**

In some cases, you can implement `ApplicationContextAware` to retrieve beans directly from the context. This is generally less preferred as it can lead to less clear code, but it's a viable option.

#### Example Using `ApplicationContextAware`

```java
@Service
public class ServiceA implements ApplicationContextAware {
    private ServiceB serviceB;

    @Override
    public void setApplicationContext(ApplicationContext applicationContext) {
        this.serviceB = applicationContext.getBean(ServiceB.class);
    }
}
```

### Conclusion

Circular dependencies can complicate the design of a Spring Boot application, but they can often be avoided or resolved through careful design and the use of Spring features. By using setter injection, refactoring code, utilizing the `@Lazy` annotation, leveraging events, or even using `ApplicationContext`, you can effectively manage dependencies in your application. Always aim for a clean and maintainable architecture to minimize such issues.

Polymorphism is a core concept in object-oriented programming (OOP) that allows objects to be treated as instances of their parent class or interface. In Java, polymorphism enables a single method or property to behave differently based on the object that invokes it. This is achieved through:

1. **Method Overriding**: Subclasses provide specific implementations of methods defined in their parent classes.
2. **Method Overloading**: Multiple methods with the same name but different parameters exist in the same class.

In the context of Spring, polymorphism can be utilized in various ways, particularly through interfaces and dependency injection. Here’s how to achieve polymorphism using Spring:

### 1. Defining Interfaces

Create an interface that defines common behaviors. Different classes can implement this interface, providing their specific implementations.

#### Example: Defining an Interface

```java
public interface Animal {
    void makeSound();
}
```

### 2. Implementing the Interface

Create different classes that implement the interface, providing their specific behaviors.

#### Example: Implementing the Interface

```java
import org.springframework.stereotype.Component;

@Component
public class Dog implements Animal {
    @Override
    public void makeSound() {
        System.out.println("Woof!");
    }
}

@Component
public class Cat implements Animal {
    @Override
    public void makeSound() {
        System.out.println("Meow!");
    }
}
```

### 3. Using Dependency Injection

Spring’s dependency injection can be used to inject the appropriate implementation of the interface. You can use constructor injection or field injection, depending on your design preference.

#### Example: Using Dependency Injection

```java
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.stereotype.Service;

@Service
public class AnimalService {
    private final Animal animal;

    @Autowired
    public AnimalService(Animal animal) {
        this.animal = animal; // Spring injects the appropriate Animal implementation
    }

    public void performAnimalSound() {
        animal.makeSound();
    }
}
```

### 4. Using Qualifiers

If you have multiple implementations and want to specify which one to inject, you can use the `@Qualifier` annotation.

#### Example: Using `@Qualifier`

```java
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.beans.factory.annotation.Qualifier;
import org.springframework.stereotype.Service;

@Service
public class AnimalService {
    private final Animal animal;

    @Autowired
    public AnimalService(@Qualifier("dog") Animal animal) {
        this.animal = animal; // Specify the Dog implementation
    }

    public void performAnimalSound() {
        animal.makeSound();
    }
}
```

### 5. Using a Factory Pattern

If the selection of the implementation needs to be dynamic, you might want to use a factory pattern.

#### Example: AnimalFactory

```java
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.stereotype.Component;

@Component
public class AnimalFactory {
    @Autowired
    private Dog dog;

    @Autowired
    private Cat cat;

                return dog;
            case "cat":
                return cat;

        }
    }
}
```

### 6. Using the Factory in a Service

```java
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.stereotype.Service;

    private final AnimalFactory animalFactory;

    @Autowired

        this.animalFactory = animalFactory;
    }

        Animal animal = animalFactory.getAnimal(type);

    }
}
```

### What is Polymorphism?

**Polymorphism** is a fundamental concept in object-oriented programming (OOP) that allows methods to do different things based on the object it is acting upon, even if they share the same name. #### Types of Polymorphism

1. **Compile-time Polymorphism (Static Binding)**: Achieved through method overloading and operator overloading.

   - **Method Overriding**: Same method signature but in a derived class.

   ```java
   class Animal {

           System.out.println("Woof");

   class Cat extends Animal {

           System.out.println("Meow");

   }
   ```

**6. What will happen if you override a method in a subclass and change the return type?**

You can change the return type of an overridden method as long as the new return type is a subclass of the original return type (this is known as **covariant return types**). If the return type does not adhere to this rule, it will lead to a compile-time error.

**Example:**
```java
class Animal {
    Animal getAnimal() {
        return new Animal();
    }
}

class Dog extends Animal {
    @Override
    Dog getAnimal() { // Covariant return type
        return new Dog();
    }
}
```

---

**7. Explain the concept of covariant return types in Java.**

**Covariant return types** allow a subclass to override a method from its superclass and return a type that is a subclass of the original return type. This enhances the flexibility of the polymorphic behavior, enabling a more specific type to be returned in derived classes.

In Java, a **collection** refers to a group of objects or a data structure that can store, retrieve, and manipulate collections of elements. The Java **Collections Framework** provides a set of interfaces, classes, and methods to handle such data structures, such as lists, sets, and maps.

Below is an overview of Java Collections Framework, its classes, interfaces, methods, and some of the newly introduced features in recent Java versions:

### 1. **Interfaces in Java Collections Framework**
The core interfaces of the **Java Collections Framework** are:

- **Collection**: The root interface in the collection hierarchy.
- **List**: An ordered collection that allows duplicates (e.g., `ArrayList`, `LinkedList`).
- **Set**: A collection that does not allow duplicates (e.g., `HashSet`, `TreeSet`).
- **Queue**: A collection designed for holding elements before processing (e.g., `LinkedList`, `PriorityQueue`).
- **Deque**: A double-ended queue that allows adding/removing elements from both ends (e.g., `ArrayDeque`).
- **Map**: A collection that maps keys to values and does not allow duplicate keys (e.g., `HashMap`, `TreeMap`).

### 2. **Commonly Used Collection Classes**
The framework provides various classes that implement these interfaces:

#### **List Implementations**
- **ArrayList**: A resizable array implementation of the `List` interface.
- **LinkedList**: A doubly-linked list implementation of the `List` and `Deque` interfaces.
- **Vector**: An old implementation of `List`, less commonly used now.
- **Stack**: A subclass of `Vector` that models a stack (last-in, first-out).

#### **Set Implementations**
- **HashSet**: A `Set` implementation backed by a hash table, which does not guarantee any specific order.
- **LinkedHashSet**: A `Set` that maintains the insertion order.
- **TreeSet**: A `Set` that stores elements in a sorted (ascending) order.

#### **Queue Implementations**
- **PriorityQueue**: A queue where elements are ordered based on priority.
- **LinkedList**: Can also be used as a `Queue` and a `Deque`.
- **ArrayDeque**: A growable array implementation of the `Deque` interface.

#### **Map Implementations**
- **HashMap**: A `Map` that stores key-value pairs, backed by a hash table.
- **LinkedHashMap**: A `Map` that maintains the insertion order of keys.
- **TreeMap**: A `Map` that stores key-value pairs in a sorted order of keys.
- **Hashtable**: A legacy `Map` class that is synchronized (less commonly used).

### 3. **Commonly Used Methods**
Here are some of the commonly used methods provided by these collection classes:

#### **Collection Interface**
- `add(E e)` - Adds an element to the collection.
- `remove(Object o)` - Removes a single occurrence of the specified element from the collection.
- `contains(Object o)` - Returns `true` if the collection contains the specified element.
- `size()` - Returns the number of elements in the collection.
- `isEmpty()` - Returns `true` if the collection contains no elements.

#### **List Interface**
- `get(int index)` - Returns the element at the specified position in the list.
- `set(int index, E element)` - Replaces the element at the specified position in the list with the specified element.
- `add(int index, E element)` - Inserts the specified element at the specified position.
- `remove(int index)` - Removes the element at the specified position in the list.

#### **Set Interface**
- `add(E e)` - Adds an element to the set.
- `contains(Object o)` - Checks if the set contains the specified element.
- `size()` - Returns the number of elements in the set.
- `isEmpty()` - Returns `true` if the set contains no elements.

#### **Map Interface**
- `put(K key, V value)` - Adds a key-value pair to the map.
- `get(Object key)` - Returns the value associated with the specified key.
- `remove(Object key)` - Removes the key-value pair for the specified key.
- `containsKey(Object key)` - Returns `true` if the map contains the specified key.
- `containsValue(Object value)` - Returns `true` if the map contains the specified value.

#### **Queue Interface**
- `offer(E e)` - Adds an element to the queue.
- `poll()` - Retrieves and removes the head of the queue.
- `peek()` - Retrieves, but does not remove, the head of the queue.

### 4. **New Features in Recent Java Versions**
Java has introduced several new features related to collections in recent versions:

#### **Java 8 (Lambda Expressions, Streams, and Functional Interfaces)**
- **Streams API**: Introduced in Java 8, the Streams API provides a way to perform functional-style operations on collections (e.g., `filter()`, `map()`, `reduce()`, `collect()`, etc.).
- **forEach()**: A default method in the `Iterable` interface, enabling the iteration of elements using lambda expressions.
- **Collectors**: A utility class in `java.util.stream` that helps to collect results from a stream (e.g., `Collectors.toList()`, `Collectors.joining()`).

#### **Java 9 (Immutability and Factory Methods)**
- **Immutable Collections**: Java 9 introduced factory methods to create immutable collections. Examples:
  ```java
  List<String> list = List.of("one", "two", "three"); // immutable list
  Set<String> set = Set.of("a", "b", "c"); // immutable set
  Map<String, String> map = Map.of("key1", "value1", "key2", "value2"); // immutable map
  ```
- **Optional.isEmpty()**: The `Optional` class now has an `isEmpty()` method, alongside the existing `isPresent()` method.

#### **Java 10 (Local-Variable Type Inference)**
- **Local-Variable Type Inference (var)**: Introduced to improve code readability, it allows declaring local variables without explicitly specifying their type. Example:
  ```java

  ```

#### **Java 11 (New String Methods)**
- **`List.copyOf()`**: A method to create an immutable copy of an existing list.
- **`Set.copyOf()`**: A method to create an immutable copy of an existing set.
- **`String.lines()`**: Splits a string into lines, returning a stream of strings (e.g., `String text = "Line1\nLine2"; text.lines()`).

#### **Java 12-16 (Preview Features and Enhancements)**
- **`Collectors.toUnmodifiableList()`**: A collector that creates an unmodifiable list.
- **Enhanced `switch` expressions**: Introduced in Java 12 and enhanced in Java 13, making switch statements more flexible and concise.
  
#### **Java 17 (Long-Term Support)**
- **Pattern Matching for `instanceof` (Preview)**: Simplifies type checking and casting.
- **Sealed Classes (Preview)**: Provides a way to define classes that can only be subclassed by a limited set of other classes.
